# 排障与已知限制

先区分信令、IP 音频、主机 USB 音频和模块蜂窝通话这几层，避免对所有问题统一增加缓存或重启整台路由器。

## 能注册但不能通话

确认手机与 N1 在同一 Tailscale 网络、YakPhone 服务器使用实际 N1 地址且协议为 UDP。关闭另一台手机上的同名账号，避免最后一次 REGISTER 覆盖接听目标。检查当前注册状态，但不要公开日志中的 Contact、号码或凭据。

SIP 5060 可达不意味着动态 RTP UDP 端口也可达。不要只开放一个猜测的固定 RTP 端口；根据自己的可信网络接口与 ACL 审核规则。不要把整个 INPUT 改成 ACCEPT，也不要创建公网 SIP 转发。

## USB 换线后没声音 / 串口变化

`/dev/ttyUSB2` 存在，不能证明服务仍握着当前那个设备。查看自己的 gateway PID 及其 `/proc/<pid>/fd/`；若串口链接标有 `(deleted)`，旧 FD 已失效，健康 API 仍可能正常。对照 sysfs 接口重新辨认 AT、备用 AT 和音频接口。

当前版本没有完整的热插拔重发现。只在无通话时，确认具体模块 USB ID 和设备路径后，恢复该模块、再重启 CellBridge。不要无差别复位 USB 总线，不要重启整个 N1/Passwall/Tailscale。先保留旧配置以便回退。

## 自己听得清楚，对方听自己卡顿

关注 iPhone → N1 上行，不只看下载测速或 VPN 注册状态。PCMU/20 ms 预期约 50 帧/秒，日志中稳定的 250 帧窗口约 5 秒；窗口明显更长表示网关收到的有效音频帧不足，但日志本身不能算出精确 RTP 丢包率。

只读抓包如需执行，应只保留包到达时间、序号、时间戳、载荷长度等元数据，不保存语音或 SIP Authorization。RTP 序号跳跃还需结合时间戳、乱序、重复及抓包程序自身丢包判断。参考 [RFC 3550](https://www.rfc-editor.org/rfc/rfc3550.html)。

Wi-Fi 正常而某个蜂窝连接卡顿时，做单变量对照：同一手机换运营商、同一 SIM 换手机、或连接另一运营商的外网热点。一次同时换手机和 SIM 的改善不能单独证明运营商或手机哪一方有问题。VPN 也不能恢复在上游已经丢失的语音。

当前接收端主要接受 RTP PT=0、160 字节载荷。没有完善的自适应 jitter buffer、PLC 或乱序重排，网络质量差时可能有明显卡顿。不要声称该限制已修复。

## 通话结束或看似突然挂断

按同一 Call-ID 看事件先后，而不是把不同通话混在一起：

- `sip bye received method=BYE`：客户端发起结束；可能是正常挂断、误触或 App/iOS 结束，网关日志不能证明用户点了哪个按钮。
- `sip call ended by modem raw="NO CARRIER"`：模块先报告结束，网关再通知手机；仅凭这一行不能区分对方挂断、蜂窝网络释放或模块问题。
- `sip await bridge failed` / `sip inbound ring timeout`：查看是否尚未接通以及具体错误。响铃超时与已接通会话不是同一回事。

procd 输出可能全标为 `daemon.err`，但应用字段 `level=INFO` 仍是信息日志；不要把标签当成故障。

## 后台 / 锁屏不响

前台 SIP 注册与 iOS PushKit 后台唤醒是两条链路。此次 N1 发布未配置或验证 YakPhone 推送认证；Pro 解锁、服务器可达和存在 Token 都不能单独证明来电推送成功。不要提交 Token 或私有推送密钥到仓库。

## 空间越来越大

根分区主要放系统依赖，不在上面放 Go 缓存。应用、数据库和运行时位于数据盘。固定大小状态报告、系统日志缓冲和有界旧日志维护能减少无意义累积，不能阻止真实短信/通话历史增长。

维护警告不等于自动删除权限。未来需要清理历史时，先确定保留期限、同步语义和备份，再设计单独流程，不直接删 SQLite WAL/SHM。
